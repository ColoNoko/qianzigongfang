# 精简测试

日常只选一种验证方式，不把下列命令依次跑一遍。

| 情况 | 命令 |
| --- | --- |
| 已知修改的源码 | `pnpm test:related src/shared/chapter.ts`（可传多个源码路径） |
| 指定测试文件 | `pnpm exec vitest run src/shared/__tests__/chapter.spec.ts` |
| 快速核心回归 | `pnpm test`，或兼容别名 `pnpm verify:quick` |
| 持续观察核心回归 | `pnpm test:watch` |
| 跨模块调整，需要完整测试 | `pnpm test:full` |
| 交付前需要类型检查、完整测试和构建 | `pnpm verify:full` |

默认核心回归固定为 8 个文件，覆盖章节识别、原子输出、导入文件保护、项目增量保存、扫描调度、目录监听、标记撤销和扫描顺序。它不等同于完整产品验收；UI 修改应选择对应页面/组件测试。

纯逻辑使用 Node 环境，确实使用 DOM 的测试通过 `@vitest-environment jsdom` 声明。视觉检查仍单独运行，普通文案/间距修改不自动启动截图或 Electron。

`test:related` 按显式源码路径和静态依赖选择测试，避免长期未提交改动使 `--changed` 每次选中整个项目。配置、动态依赖或跨层改动应主动选择相关集成测试或完整套件。

2026-10-07 本机结果：默认 8 文件 / 118 项，Vitest 耗时 3.13 秒；完整 134 文件 / 1335 项通过。耗时不包含 pnpm 启动，后续会随机器和测试变化。数据持久化、迁移、导入及关键交互测试继续保留；本轮删除的是低价值示例、静态布局/源码写法断言和重复旧实现对照。
